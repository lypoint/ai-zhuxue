# 学生 Web 完善方案与工作量评估

评估日期：2026-10-24。依据当前工作区代码静态核查与平台官方资料；不是线上或真机验收报告。人日为工程估算，不是已实测工时。

> 历史评估，非当前部署指南：React/TypeScript 双端已上线，旧 `server/app/web_page.py` 已移除，`/web` 返回 410。当前品牌、域名与部署流程见 [部署与运维](deployment.md#6-google-play-海外双端-web)，实际验收与延期真机项目见 [Web 验收记录](web-acceptance.md)。下文的旧页面现状、缺口与工时保留用于追溯。

> 范围已调整：用户随后明确 Web 同时包含学生端和家长端，仅面向非中国市场，独立部署至 Google Play 渠道官网，国内官网移除 Web。新的技术选型以 [海外双端 Web 技术方案](web-international-architecture.md) 为准。本文件保留学生端功能差距、平板与白名单分析；“继续扩展内嵌页面”的建议和学生端单独工期不代表新范围的总方案。

## 结论与建议范围

可在现有 FastAPI + HTML/JavaScript Web 上增量完善，复用学生 App 已使用的后端接口。优先完成 iPad Safari 和指定 Android 平板浏览器的文字、图片学习流程，再补成绩、学习反馈等功能。无需为此重做后端学习围栏、老师系统、图片审核或家长管理端。

建议先交付 A+B（含图片的平板学习版）：基础估算 18–26 人日，加约 20% 风险余量后为 22–32 人日。继续补齐本报告 C 中的主要学生功能，累计基础估算 26–38 人日，含余量 32–46 人日。设备管理、整机锁定、家长 Web 和支付不在此范围内。

当前 `web_page.py`、`main.py`、README 和 Web 服务测试仍写明“仅聊天／范围冻结”。本报告是扩展提案；实际实施时需要同步更新这些范围描述和对应测试，保留家长审查／管理仍在家长端的边界。

## 二、实现路线

### 1. 保留现有 Web，先做有限拆分

把内嵌 HTML、样式和脚本拆成少量同源静态文件，建立 API、聊天状态、附件、学习页面这些清楚的职责；继续由当前服务提供 `/web` 与静态资源。沿用现有渲染库，不引入新的前端框架或单独的 Node 生产服务。

此路线可复用后端规则与数据，新增构建和部署要求较少，也便于把脚本、公式字体全部放在同一个域名下。测试所需开发依赖单独管理并锁版本。

不将“把 Flutter App 编译为 Web”作为默认方案：它可能复用部分 Dart 页面，但仍需验证扫码、图片选择／裁剪、浏览器存储、网络层、首屏资源及平板键盘；本次未编译验证，不能把这些视为已经解决。若未来要统一两端 UI，可另外做 2–3 人日原型比较；这不计入下述默认路线。

### 2. 平板布局与输入

- 优先支持 iPad Safari，其次 Android Chrome 和一款确认有目标用户的国内厂商浏览器；浏览器型号与系统版本作为验收清单的一部分，不宣称覆盖所有 Android 浏览器。
- 初始断点建议：可用宽度至少 1024 CSS px 时侧栏常驻，768–1023 时紧凑导航／抽屉，更窄时退为单列。iPad 分屏或窗口缩小时按真实可用宽度切换，不按设备型号判断。
- 输入改多行；触屏显式按钮发送；外接键盘提供清楚的发送／换行规则，必须处理中文输入法 composition，不能按回车选字时误发送。
- 使用动态视口和安全区，必要时用 VisualViewport 修正键盘覆盖；不禁止用户缩放。iPad 虚拟键盘可能改变 visual viewport 而不改变布局 viewport，不能只把 `100vh` 换成 `100dvh` 就视为完成。
- 支持横竖屏、浏览器工具栏收起／展开、主屏幕模式、长公式／表格局部横向滚动；主要触控目标建议至少 44 CSS px。
- 回看历史时不强制滚到底；新回答提供回到底部提示。切会话／切老师／打开收藏时隔离当前请求，避免旧回答插入新页面；生成期间默认禁止危险切换，或明确确认后退出。

### 3. 文字聊天、登录与限制

- 用 `fetch` 的 POST 响应流解析现有 SSE，保留 Bearer 头；原生 EventSource 不是当前 POST + Authorization 协议的直接替代品。处理分块 UTF-8、事件边界及 `meta/delta/replace/done/error`。
- Web 默认使用后端的先审核后回放模式，不为追求首字速度自动加 `live=true`。当前 App 纯文字请求会加该参数，Web 不需要照搬；须在等待阶段显示“老师正在思考／检查”。解析替换事件也须使用同一消毒和渲染流程。
- 保存已入库的用户消息 ID；网络结果不确定时先拉取会话核对，不自动重发新的问题；只有满足后端重试条件才传 `retry_message_id`。没有入库凭据则恢复草稿，让用户确认再发。
- 401 清理当前学习状态和 token，停止后台请求，回到绑定页；423 显示休息状态；429 分别说明次数／时长等限制；503 保留草稿或已保存问题。静默吞异常改为可见且可重试的状态。
- 老师渠道说明已按当前实现更新：国际 Web 家长端与学生端经 `BrowserMiddleware` 统一使用 `googleplay`，展示已启用的 `googleplay` 与 `all` 老师，默认老师使用 CMS 的 Google Play 渠道配置；iPad 等设备访问不会自动切换为 App Store 渠道。普通 API 未携带 `X-App-Channel` 时仍默认为 `wechat`，该缺省规则不适用于国际 Web 入口。老师渠道与支付来源独立，详见[老师渠道配置](teacher-channels.md)。
- 前台显示学习状态，后台或锁屏暂停累计，恢复时重新检查可用性并核对会话。使用可见时间区间而不是“定时器触发次数×60”。
- 同源多标签选一个可见页面负责上报；计时尾段尽力结算；后端按需要增加上报去重、时间范围校验和跨日归属，保持旧 App 协议兼容。退出、401 时停止计时。不要把离线重传或 pagehide 请求成功当成保证。
- 现有时长限制依赖客户端上报，服务端目前主要在新请求时检查额度。改进上述统计也不等于防篡改或精确切断在途回答；服务端学习租约／强制中断属于另行估算范围。

### 4. 图片学习

复用老师能力接口、`/media/uploads`、附件完成审核、`asset_ids`、`content_blocks`、配图任务接口，避免重新实现图片审核和模型调用。

先支持历史／收藏附件和生成图片显示，再做拍照、相册、预览、旋转／裁剪、缩放压缩、删除、上传重试、最多三张和纯图片发送。客户端检查不能替代后端格式／尺寸／审核检查；沿用默认单张 8 MiB、2000 万像素等服务端配置。

iPad 相机和相册的 HEIC／HEIF、EXIF 方向是验证重点。目前服务端文档只承诺 JPEG/PNG/WebP；支持浏览器能解码的图片可转 JPEG，无法解码时必须明确提示更换格式，不能只改扩展名。如果目标设备普遍输出无法解码的格式，需要另行补转码支持。

私有附件按 asset ID 鉴权，过期后重新取访问凭据；图片错误不影响已完成的文字。配图任务在可见页面内轮询，恢复时重新获取状态，不因刷新重复创建付费任务。

## 三、网站白名单适配

### 1. 区分两种白名单要求

| 模式 | 浏览器侧要求 | 实现选择 |
|---|---|---|
| 本站 + 必要资源域名 | 允许本站，并允许确切的七牛上传／私有下载域名；不得放开整片供应商域名 | 使用已有直传和签名下载协议，配置精确来源 CORS；A+B 估算默认采用此模式 |
| 严格单域名 | 浏览器全部网络请求只到本站；不靠重定向访问七牛 | A 同源化脚本／字体，B 额外增加同源上传和图片字节读取通道；额外 3–5 人日 |

当前三类渲染库（marked、DOMPurify、KaTeX）的脚本与样式来自 `cdn.jsdelivr.net`，KaTeX CSS 还引用字体。必须一起迁移并固定版本、保留许可证；只下载 JS 不足以实现单域名。初版不依赖外部字体、第三方统计或浏览器直连模型接口。

当前图片流程让浏览器直传七牛，并通过 `/media/{asset_id}` 返回五分钟签名 URL；仅把该 JSON 接口放到本站或把图片域名重定向到七牛，都不满足严格单域名。

严格模式应提供两条受控通道：

1. 学生鉴权的图片上传，由服务端接收受限文件并转存／复用审核；不要开放接受任意目标 URL 的上传代理。
2. 按 asset ID 鉴权后读取图片字节。保留家庭／设备／审核状态检查，限制大小、类型和超时；可采用带 Bearer 的 fetch 后生成临时 blob URL 展示，退出时释放，不把长期 token 放到图片 URL。

需评估图片进出服务器的额外带宽和并发；部署文档同步请求体限制、超时和流量观察。七牛存储与审核、模型提供方仍由服务端访问，不应加入孩子浏览器白名单。

### 2. 不允许正文成为白名单逃逸入口

- Markdown 消毒之外，还要处理外部链接、图片和自定义协议。外部图片默认不加载；不把模型输出的外部 URL 当作可信私有附件。
- 学习版对外链默认显示地址／提示由家长处理，不直接打开新窗口或唤起其他 App；阻止 `intent:` 等非预期协议。同源链接只开放实际需要的学习路由。
- Web 静态资源和 API 同源；只为 Web 文档配置适当的 CSP，限制脚本、连接、图片和字体来源；需要的 blob 图片来源显式允许。CSP 不能代替设备网站白名单。
- 通用模型调用、存储密钥不下发浏览器。缓存策略区分公开静态资源和私有学习数据；不使用 Service Worker 缓存 token、聊天记录、签名图片和动态 API。

### 3. 家长配置与主屏幕入口

提供 Apple 网站白名单／引导式访问说明及已验证 Android 方案说明。应用自身不检测或宣称已获得整机锁定能力；网站白名单不等于禁止游戏、其他 App 或整机所有网络连接。MDM/Kiosk 是独立设备管理工作。

主屏幕图标／manifest 是便捷入口，不承诺锁定或离线可用。首次引导建议先确定使用浏览器还是主屏幕入口，再完成绑定；不可假定两个入口共享全部本地存储。存储失效应回绑定页，不使用设备指纹“恢复”身份。

现有绑定策略会在同一孩子新设备绑定时撤销旧设备和旧 token。因此 App、不同浏览器和主屏幕入口之间可能发生重新绑定冲突：须明确说明，验证家长“重绑已有孩子”流程，不能清掉浏览器数据后就引导新建孩子或误占新名额。本项目若要同时允许 App 与 Web 使用同一孩子，是后端设备／权益政策变更，另行评估。

假设一名熟悉本项目的全栈工程师投入，复用当前后端，测试设备与测试配置可取得；每人日约 8 小时。各阶段包含功能验证，专门真机回归另列。基础估算不含等待设备／凭据、发布审批和生产第三方故障。

## 五、验收门槛与优先验证

建议 A1/A2 开始时先完成三个风险验证，再锁定完整排期：iPad 中文键盘＋分屏；图片资源在目标网站白名单中的实际拦截范围；Safari／主屏幕绑定与已有 App 的冲突表现。此验证纳入 A 的工时，不额外重复计费。

| 场景 | 必须看到的结果 |
|---|---|
| iPad Safari 与主屏幕模式 | 绑定、中文输入、键盘开合、横竖屏、分屏都能正常发问和阅读；缩放不被禁止 |
| Android 平板 | Chrome 和选定厂商浏览器分别验证；拍照、相册、返回键、键盘、浏览器恢复不丢已保存问题 |
| 生成时切换／网络中断 | 回答不插入错误会话；不自动重复付费提问；恢复先核对记录；没有 done 不伪装成功 |
| 家长修改限制／撤销设备 | 回前台检查；新请求仍受服务端限制；401 回绑定，不无限请求；不把旧内容当新回答 |
| 计时 | 隐藏标签页／锁屏不持续累计，尾段结算、多标签不重复累计、跨日正确；强杀尾段可能丢失的边界如实说明 |
| 白名单 | 冷启动、清缓存后公式与字体仍正常；API、老师头像、历史与新图片可用；无需放开 jsDelivr、Google 登录或模型站点 |
| 图片异常 | HEIC 不支持时明确提示；旋转／裁剪正确；上传拒绝／超限／审核失败均可恢复；五分钟后图片可重新授权加载 |
| 安全与隐私 | HTML／脚本不能执行，正文外链与图片不逃逸；跨家庭附件被拒绝；退出不保留可继续访问的应用内私有缓存 |
| 升级 | 旧 App 请求保持兼容；旧 Web 缓存不会加载不匹配的新脚本；生产已有 App 和 CMS 不受 Web 路由改造影响 |

现有 Python API 测试继续复用，新增浏览器测试聚焦绑定、SSE 边界／失败恢复、休息／401、计时多标签、附件和白名单资源请求；自动化可用桌面 Chromium/WebKit 做回归，但不能替代真实 iPad Safari 和 Android 平板。Android 设备操作统一使用 ADB。

当前尚未进行真机、真实存储与生产代理联调，也未运行产品功能测试，因为此次只做评估。实际开工前需取得目标设备／系统／浏览器清单和测试环境。真实生产发布仍须遵守 `AGENTS.md`、部署文档及私有生产配置要求，不从历史产物猜参数。

## 六、官方资料

- [Apple 家长控制与网站限制](https://support.apple.com/zh-cn/105121)：网站批准与设备 App 管理是不同控制项。
- [Apple 引导式访问](https://support.apple.com/en-ie/111795)：临时锁定单 App，不自行提供单网站白名单。
- [Google 网页 Kiosk 示例](https://developers.google.com/android/management/policies/dedicated-devices)：受管设备可组合 Kiosk、Chrome URL 禁止列表与允许列表。
- [MDN Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)：后台计时器会被限制，可见状态需显式处理。
- [MDN VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)：屏幕键盘与可视视口的差别。
- [MDN EventSource 构造接口](https://developer.mozilla.org/en-US/docs/Web/API/EventSource/EventSource)：原生接口只接受 URL 和 credentials 选项，不直接适配本项目 POST + Bearer 请求。
- [MDN capture 属性](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/capture)：相机选择依赖设备和浏览器支持，不能仅写属性就视为真机验收。
- [WebKit 主屏幕 Web App](https://webkit.org/blog/13878/)：manifest 和 standalone 入口能力；不代表整机锁定。

本次未实施 Web 功能、Flutter Web 迁移、家长 Web、支付、语音、离线学习、推送、MDM/Kiosk 或多设备同时登录；这些不应被计入上述版本的能力承诺。
