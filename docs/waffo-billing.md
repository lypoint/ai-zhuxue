# Waffo Web 订阅

注册即获得 3 天免绑卡试用、1 个学生名额。符合资格的家庭通过认证收银台开通 Waffo 原生 30 天免费试用，结束后首次扣款、按月续费，直至取消。两段试用重叠，注册试用剩余时长不补赠；立即订阅共约 30 天免费使用，用完 3 天再订阅共约 33 天。若中途停用后才订阅，累计免费使用时长与注册至首扣的日历跨度不同。

## 配置

见 server/.env.example：WAFFO_ENABLED、WAFFO_ENVIRONMENT、WAFFO_MERCHANT_ID、WAFFO_STORE_ID、WAFFO_PRIVATE_KEY_PATH、WAFFO_WEBHOOK_PUBLIC_KEY_PATH、WAFFO_TEST_ACCOUNT_TOKENS；STORE_PRODUCTS_JSON 的 waffo 字典映射以上四个代码至真实 PROD_ ID。保留原 STORE_TOKEN_SECRET，不能换密钥导致历史账本无法解密。

迁移 5b8c0d2e4f60 将仍为默认 30 天的数据库定价配置改为 3 天，解决已运行实例不读取环境默认值的问题；不删家庭或支付数据，不批量截断已有家庭权益。

## 接口

- GET /parent/waffo/catalog：四档美元目录、环境标记。
- POST /parent/waffo/checkout：验证套餐、名额、跨渠道互斥、已有订单；创建短期认证收银台。未提交且仍有效的同套餐会话复用，买家 token 每次重新签发。
- POST /parent/waffo/verify：reference 为应用业务订单号或 ORD_ ID；重新查询权威订单、家庭、环境、商品版本、周期、付款及退款状态，再写既有加密账本。
- POST /parent/waffo/refresh：刷新当前家庭的远程订阅，支持回跳遗失或清理浏览器缓存后的恢复。
- GET /parent/waffo/manage：为当前家庭即时签发消费者门户链接，响应 no-store；链接不可记录或缓存。
- POST /payments/waffo/notify：原始请求体 RSA 验签、64 KiB 上限，校验商店及环境。原始签名允许最多 45 分钟重试、最多 1 分钟未来时钟偏移；按事件类型、eventId（缺失时回退 id）及原始 timestamp 去重，持久重试并周期对账。

原生试用状态独立为 subscription_trial，按所选套餐授予权益，不生成实付统计、不补赠本地试用。canceling 保留当前周期权益，canceled/退款/争议按权威状态撤回。零元试用付款的 isFullyRefunded=true 不代表退款，不得撤权。past_due 保留短暂恢复窗口，最长到当前周期开始后 48 小时，不因一笔未付续费授予整月。退款不会自动停止 Waffo 续费，支持操作必须另行取消。

## 退款支持操作规程

官网承诺首次成功扣款后 7 个日历日内申请全额退款，不设用量门槛；计时起点是首笔成功实付，不是注册日或免费试用开通日。客服核对购买家庭、订单、付款时间、金额、币种和既有退款；不能要求完整卡号或安全码。按官网时限在 2 个工作日内回复，确认的计费错误在 5 个工作日内处理，获准退款在 5–10 个工作日内原路发起，并跟进实际处理结果。法律适用与特殊情形仍按已发布条款处理。

1. 从 Waffo 权威订单找到对应的成功付款，用同环境商户密钥调用 `POST /v1/actions/refund-ticket/create-ticket`，指定 paymentId、原因、展示单位金额和原币种。美元 14.99 在 REST 写 `"14.99"`，GraphQL 为 `1499` 分；不得混用。使用唯一业务退款编号，并在超时后先查已有 ticket/refund，不能盲目重复提交。
2. 首月全额退款同时单独取消续费，并查询 `willRenew=false`。退款成功不会自动关闭 Waffo 续费；本地显示撤权或 auto_renew=false 不能代替平台确认。欠费账单与取消状态也要核对。全额退款撤回该付款对应的当前会员权益；仍有效的独立注册试用不删除。
3. 重复扣款只退错误付款，不能把合法的当前订阅一并取消。超过 72 小时服务中断按条款计算比例退款或展期；比例退款保留未退部分对应的权益，不默认取消续费。退款 API 可能限制一笔付款已有退款后的再次退款，先核对平台记录；剩余退款受阻时向平台支持升级处理，不重新扣款、不降低已承诺的应退总额。
4. API 返回 `processing` 仅代表已受理，须继续查到 `succeeded`，核对退款金额、币种、`testMode`、平台通知投递成功及本地收件 processed。失败或长期 processing 须跟进，不能向客户宣称已到账。已结算交易可能受商户可用余额限制；保留充足退款资金，不能将平台费用转嫁为全额退款扣减。
5. 当前支持入口为官网联系邮箱、商户后台及商户 API，未增加面向客户的自动退款按钮。客服需留存申请时间、政策依据、应退/已退金额、退款工单、续费关闭确认及处理回执，避免超过承诺时限。

官方依据：[退款 API](https://docs.waffo.ai/api-reference/endpoints/refunds/create-refund-ticket)、[订阅退款](https://docs.waffo.ai/guides/refunds)、[取消订阅](https://docs.waffo.ai/api-reference/endpoints/subscriptions/cancel-subscription)。实际沙箱验证表明订阅付款可使用该退款 API，不能根据其他概述页的不同表述认定订阅不可退款。生产银行卡实际原路到账、结算后余额约束及人工客服响应时限仍需运营保障；沙箱成功不等于这些生产环节已验收。

## 回调失败与积压监控

候选代码新增管理员鉴权接口 `GET /admin/billing/notification-health`，仅返回各渠道待处理数量、最久等待秒数和最多失败次数，不返回家庭、订单、邮箱、令牌或原始通知。CMS 概览登录后每 60 秒更新；查询失败明确显示监控不可用。

应用重试任务每轮检查收件：任一渠道等待达到 10 分钟、失败达到 3 次或积压达到 100 条即告警。首次处理失败记录 `STORE_CALLBACK_FAILED`，Waffo 处理异常返回 503 并记录 `WAFFO_CALLBACK_FAILED`；持续积压记录 `STORE_CALLBACK_BACKLOG`，每 15 分钟提醒一次，恢复记录 `STORE_CALLBACK_RECOVERED`。重试基础设施不可用记录 `STORE_RECONCILIATION_UNAVAILABLE`。记录不包含异常原文、请求头或付款资料。

生产发布后应将这些错误标记接入已有运维日志告警，并定期检查 CMS；本轮只提供日志与 CMS 告警，未配置邮件/即时消息外发，也不能用此接口代替进程存活或公网可达性监控。排查顺序：服务和数据库健康 → Waffo 投递状态/HTTP 状态 → 本地待处理数量及失败次数 → 权威 API 可用性、配置和签名时钟。恢复后确认 processed、积压归零及权益正确，保留证据。不得为了消除告警直接将生产事件标为已处理或修改家庭权益。
