# 账号删除

所有家长端渠道共用“家庭账户 → 删除账号”。页面说明范围、30 天处理期、支付/安全记录及备份保留，以及 Firebase 安装数据无法按家庭账号定位的限制。用户输入 `DELETE` 并确认后才提交；可先通过现有商店管理入口取消续订。账号删除不自动取消 Apple/Google Play 订阅或退款，也不要求先取消订阅才能申请。

`POST /parent/account/deletion-request` 使用当前家长 JWT，body 为 `{"confirmation":"DELETE"}`。请求持久化至 `account_deletion_requests`，返回 202 后清除客户端登录凭证，并展示可复制的 `AD-家庭ID` 申请编号供客服查询；编号本身不提供任何访问权限。家庭及所有关联学生立即停用，设备和绑定码撤销，正常 API 和各登录方式均无法继续访问。网络响应丢失可用原 JWT 重试同一申请，不产生重复工单；该 JWT 不能访问其他家庭接口。多监护人的共同家庭不自动删除，返回支持邮箱，避免一位监护人删除另一位的数据。

## 运营处理（必须纳入日常值守）

这是一条人工处理删除申请的流程，**不会仅凭提交自动执行彻底删除**。在 API 运行环境加载生产环境变量后，每个工作日查看队列，确保 30 天内处理；以下命令不包含任何真实账号或凭据。

```sh
python -m app.account_deletion list
python -m app.account_deletion complete --family-id FAMILY_ID --confirm-family-id FAMILY_ID
```

只处理已有申请；第二个参数必须重复同一家庭 ID。不可逆清理至少等待申请后 24 小时，让此前在途的聊天和评估写入结束，再在一个事务中清除账号身份/密码、孩子个人资料、设备、绑定码、消息、围栏/举报/反馈、收藏、时长与用量、成绩及版本、评估及审计、奖励、通知和家庭设置。重复处理已完成申请无副作用。该命令不得用于审核完成后的普通停用；审核账号停用仍使用原 `review_account disable`，不要误删审核资料。

保留无登录能力的主体 ID 壳，避免旧 JWT 的 ID 被新账号复用；保留隔离的商店订单、交易、购买令牌及结算/退款/防重复归属记录，旧订阅不会自动转给新注册家庭。支付通知即使继续到达也不能恢复家庭访问。安全操作日志及删除申请完成记录用于追踪处理结果，不包含新增手机号、邮箱或聊天内容。

完成数据库清理后，还必须按实际法律义务复核支付和安全记录保留范围、请求第三方处理可定位的数据，并按备份轮换策略清除备份。数据库恢复前重新应用已完成删除清单，防止从备份恢复已删个人信息。Firebase 未设置 Analytics User-ID，无法凭家庭 ID 清除某个安装实例；不要宣称本命令会清除全部 Firebase 或 AI 提供方数据。客服通过 support@gker.net 处理进度查询、部分数据删除、共同家庭及可定位的第三方数据请求。所有操作/恢复清单存放私有 `credentials/`，不得提交开源仓库。

## 发布

先发布 API 并应用 `d8e9f0a1b2c3` 迁移，再发布客户端。新客户端依赖该接口，旧 API 会返回 404；失败时不会清除本机登录。同步线上隐私政策的删除入口说明后再提供新版本供审核。Data Safety 的账号/部分数据删除外部入口仍为 `https://gker.net/privacy/#deletion`。不能把“申请已接收”显示为“全部数据已删除”。
